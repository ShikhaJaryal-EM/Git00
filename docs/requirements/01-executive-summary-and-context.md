# Executive Summary and Context

## Executive Summary

- Local tool that captures and maintains employee details
- Each record has first name, last name, and active or inactive status
- A user can create, edit, deactivate, and reactivate a record
- The employee list is still available after the tool is closed and opened again
- Runs on a local machine with no cloud or other outside services
- A basic working interface is required; visual polish is not
- Security, roles, and permissions are not required

## Business Context

- Teams need a reliable record of who is on staff and whether each person is active
- The record is used to look people up, add new people, correct names, and mark people inactive
- The work must be accurate
- The record must be available without an external system

## Current State

- Employee names and status are not captured in a dedicated local tool
- There is no agreed place to create, correct, or reuse the same employee list across sessions

## Problem Statement

- There is no dedicated local place to keep employee names and status
- New employees cannot be recorded in a reusable list
- Existing names cannot be corrected in one agreed place
- Active or inactive status cannot be maintained consistently
- The same employee list cannot be reused after the tool is closed
